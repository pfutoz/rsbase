🚨 1. テーブル構成・スキーマの絶対変更禁止規定（最重要ルール）
⛔ 【厳格禁止】RS-Base データベースに対する構造変更およびデータ更新の絶対禁止:
本システム（index.php, viewer.php 等）が接続している PostgreSQL データベースは、院内の医療画像・波形ファイリングシステム「RS-Base」本体が全権管理・リアルタイム運用しているコアデータベースです。
このデータベースに対してテーブル定義の変更や直接更新を行うと、RS-Base本体のCGIエラー、DICOM受信用デーモンの停止、最悪の場合は医療画像データの消失・整合性破壊に直結します。
したがって、以下の運用原則を開発者および保守担当者の絶対遵守事項として定めます。

禁止事項リスト

区分禁止される操作内容禁止理由
DDL操作の禁止
（スキーマ・構成変更）		 ・CREATE TABLE / DROP TABLE
・ALTER TABLE（カラム追加・削除・型変更）
・CREATE INDEX / DROP INDEX 		RS-Base本体のCGIプログラムは固定カラム位置や既存インデックスに強く依存しているため、構成変更によりRS-Base本体が即座に動作停止します。
DML操作の禁止
（データの直接更新）		 ・INSERT INTO
・UPDATE
・DELETE FROM / TRUNCATE 		RS-Base独自の採番体系（renban, sort, again_on 等）や整合性チェックを迂回した更新は、カルテリンク破綻や二重登録を引き起こします。
トリガー・ストアド変更 ・トリガーやルールの新規追加・変更 データベース内部のイベント処理競合を防止するため。
💡 許容される操作（唯一の利用形態）:
本再構築システム（PHP）に許可されている操作は、SELECT による純粋なデータ参照・抽出（Read-Only）のみです。新規データの登録や所見の修正は、必ずRS-Base本家の編集画面（2000.cgi）を通じて実施します。

⚡ 5. PHPからのクエリ設計 & 参照最適化

RS-Baseサーバーへの負荷を最小限に抑えつつ高速にデータを引き出すため、index.php では以下の実装パターンが徹底されています。

① プレースホルダーを用いた安全なパラメータバインド

// 日付前方一致または患者ID完全一致の安全なクエリ構築
$sql = "SELECT renban, id, kanja_kanji, kanja_yomi, kensamei, date, sindan1, folder, sex, age FROM gazou_tbl WHERE 1=1";
$params = [];

if (!empty($filter_id)) {
    $sql .= " AND id = ?";
    $params[] = $filter_id;
} else {
    $sql .= " AND date LIKE ?";
    $params[] = $target_date . '%';
}
$sql .= " ORDER BY id DESC, renban DESC";

$stmt = $pdo->prepare($sql);
$stmt->execute($params);

② 必要最小限のカラム指定

SELECT * は避け、画面描画に必要なカラムのみを射影することで、PostgreSQL側のメモリ転送量およびネットワーク帯域を節約しています。
