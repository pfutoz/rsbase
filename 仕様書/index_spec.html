RS-BaseのPostgreSQLデータベース（gazouDB）を直接参照し、院内診察端末から瞬時に検査画像・心電図・カルテへアクセスするためのメインWeb画面の全体機能仕様です。

🚀 1. システム全体概要 & 再構築の背景

当院で稼働している RS_Base は、内視鏡・超音波（US）・心電図などのDICOMデータや波形データを一元管理するWebファイリングシステムです。しかし、本家の標準Web画面（CGIベース）は動作が重く、診察時の画像閲覧に待ち時間が発生していました。

そこで、PHP + PostgreSQL直接クエリ + 非同期トリガー連携 により、以下の目的を満たすフロントエンドとして index.php が開発・稼働しています。

  • 極めて高速な一覧表示: RS-BaseのPostgreSQL（gazouDB）から当日の検査一覧を即座にフェッチ。
  • 多様な外部連携: 通常DICOMビューワ（rsview.exe）、フクダ電子心電図ビューワ（FEV-05.exe）、電子カルテ（karteview.php）、胃がん検診DICOM→JPEG一括変換（dicom_convert.py）へのシームレスな連動。
  • ゼロインストールWeb運用: 医師・スタッフはWebブラウザ（Chrome / Edge 等）から一覧を閲覧・操作可能。
⚠️ 【絶対厳守】データベース構成・データの変更禁止（Read-Only）ルール:
本システムが参照するPostgreSQL（192.168.1.164 / gazouDB）は、RS-Baseパッケージ本体が運用・管理しているマスターデータベースです。
テーブル構造（DDL）の変更、カラムの追加・削除・変更、インデックスの変更、およびデータの直接更新（INSERT / UPDATE / DELETE）は一切厳禁（絶対NG）です。本PHPは純粋な SELECT による参照専用（Read-Only）として開発・運用されています。
🎛️ 2. 画面構成 & 3つの動作モード

画面上部のモードセレクタにより、用途に応じた3種類の起動モードを切り替えることができます。

動作モード GETパラメータ 概要・動作仕様

(直起動・標準推奨)		 ?mode=custom
デフォルト		 検査名バッジクリック時に非同期POSTでサーバー上の tmp/trigger_[IP].txt を生成し、クライアントPC常駐の watcher.vbs 経由で rsview.exe（通常画像）または FEV-05.exe（心電図）をミリ秒で直起動します。
RSBaseモード
(本家標準CGI連携)		 ?mode=rsbase

胃がん検診
JPEG変換モード		 ?mode=jpeg
一括変換モード		 検査名バッジのクリック時にもJPEG変換トリガー（launch_mode=JPEG）を発行します。常駐ソフトがInputBoxダイアログを表示し、PythonによるDICOM一括JPEG変換ツールを実行します。

画面コントロール部

  • モード切替プルダウン: rsbase / custom / jpeg を選択するとURLパラメータを更新して即時リロード。
  • 日付ナビゲーション: 「◀ 前日」「翌日 ▶」ボタン、および <input type="date"> によるカレンダー選択（当日: date('Y/m/d') が初期値）。
  • 患者絞り込み解除ボタン: patient_id 指定中に表示され、通常の日付表示一覧へワンクリックで復帰。
  • 常駐スクリプトDLリンク: watcher.zip を直接ダウンロードできるボタン（custom または jpeg モード時に表示）。
  • ヘルプ・マニュアルリンク: help.html（ヘルプ）および igankenshin.html（胃がん検診マニュアル）への外部リンク。

🔍 4. 検索・絞り込み & クライアントサイド動的ソート

画面リロードを伴わずに瞬時に該当行をフィルタリング・並べ替えできるクライアントサイドJavaScript機能を備えています。

① 検査種別トグルフィルター（kensaToggleContainer）

当日データに存在するユニークな検査名（内視鏡、US、心電図など）をPHP側で抽出し、動的ボタンを生成。クリックすると data-kensamei 属性に合致する行のみを瞬時に表示します。

② よみがな五十音抽出トグルフィルター（initialToggleContainer）

「すべて」「ア行」「カ行」〜「ワ行」等のボタンをクリックすると、患者よみがなの先頭1文字（data-yomi）を判定し、五十音行でフィルタリングします。検査種別フィルターとの複合絞り込みも可能です。

③ テーブルソート機能（sortTable(column)）

テーブルヘッダーの「検査ID」「患者氏名 (よみ順)」「検査名」をクリックすることで、JavaScriptがDOMテーブル行をインメモリで昇順/降順にトグルソートします。

  • 検査ID: localeCompare(..., {numeric: true}) により自然な数値順でソート。
  • 患者氏名: カタカナよみ（kanja_yomi）の日本語50音順でソート。
  • 検査名: 検査名文字列の五十音・アルファベット順でソート。
⚡ 5. 非同期トリガー生成API仕様（AJAX通信）

Webブラウザからクライアント端末常駐の watcher.vbs へ起動命令を伝達するためのバックエンド仕様です。

エンドポイント仕様

URLindex.php
HTTPメソッドPOST
Content-Typeapplication/x-www-form-urlencoded
レスポンス形式application/json; charset=UTF-8

リクエストパラメータ

パラメータ名型必須説明
actionString○launch 固定
folderString○開く対象のDICOM/画像フォルダのUNCパス（例: \\192.168.1.164\...）
launch_modeString○NORMAL（通常画像）、ECG（心電図）、JPEG（胃がん検診DICOM変換）

サーバー側処理フロー

  1. リクエスト送信元クライアントのIPアドレスを $_SERVER['REMOTE_ADDR'] より特定。
  2. tmp/ ディレクトリの存在を確認（なければ mkdir(..., 0777, true)）。
  3. ファイルパス tmp/trigger_[クライアントIP].txt をターゲットに指定。
  4. 書き込み内容 [launch_mode]|[folder]（パイプ区切り）をファイルに書き出し。
  5. 成否に応じて JSON を返却： 
    // 成功時
{"status": "success"}

// 失敗時
{"status": "error", "message": "トリガーファイルの書き込み失敗: ..."}
